## Plan

Started in [increment 170](RUST-INCREMENT-170.md). It proceeds one step at a
time, each a small reviewed PR:

1. **L2 to Rust evidence**, one L2 family per increment, in
   [TRACE-L2.md](TRACE-L2.md). Each requirement gets a disposition and cited
   tests or code. `scripts/check_trace.py` (CI `admin-ui` job) checks the IDs
   and cited tests and reports the mapped count.
2. **Decisions for the user**, collected as they arise and never made alone:
   - deviations (Rust meets the intent differently);
   - proposed "not applicable" requirements (for example Python-era
     mechanisms, or features outside the Rust first release);
   - rewording.
3. **L3 — retired by user approval 2026-11-22:** preserve the earlier Python
   [L3](L3-REQ.md) unchanged below its retirement header. Write Rust L3
   obligations only where a test plan needs them, using new IDs; retired IDs
   are never reused.
4. **L1 roll-up:** [TRACE-L1.md](TRACE-L1.md) is generated by
   `python3 scripts/trace_l1.py --write`; CI runs the script without `--write`
   to reject drift. The worst child decides: approved backlog Deviation/Open
   means Backlog; otherwise Partly tested/Inspection means Partly traced;
   otherwise all Tested/Out of scope (approved) means Traced. No children
   means Backlog for missing derivation, never automatic verification.
